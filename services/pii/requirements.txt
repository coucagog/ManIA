# Versions EPINGLEES depuis le §57.

# Pourquoi : ce fichier n'etait fait que de fourchettes (`spacy>=3.7,<3.9`...).
# Consequence directe — un `docker compose build` ne reconstruisait PAS l'image
# qui tourne : il resolvait ce qui existait sur PyPI CE JOUR-LA. Autrement dit
# le service en production n'etait pas reproductible, et un rebuild de routine
# (ajout d'un module, changement du Dockerfile) pouvait embarquer un spaCy ou un
# Presidio different sans que rien ne le signale. Sur un service dont le role est
# de NE PAS laisser passer d'identifiant, un changement silencieux de modele de
# detection est exactement ce qu'on ne peut pas se permettre.
#
# Ces versions sont celles effectivement installees et mesurees au §57
# (Python 3.11.9, meme mineure que l'image `python:3.11-slim`).

# hors-ligne (test_pii_engine, test_wire, test_sse) ET le banc de rappel avant
# de deployer. Une mise a jour de spaCy peut deplacer les entites detectees.
